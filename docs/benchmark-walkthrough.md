# 从零给 CodeAgent 做评估：按步骤操作的教程

适用环境：Windows，项目在 `D:\new_codeAgent`。本教程是操作说明，评测程序还没有因为写了这篇文档就自动存在。

你不用一次读完。先做第 1–5 步，完成一道练习题；然后再做批量对照。旧版 [benchmark-design.md](D:/new_codeAgent/docs/benchmark-design.md) 保留为技术细节参考，先不用看。

## 先弄明白：你到底要做什么

不是问 AI“你觉得我的框架好不好”，而是给 CodeAgent 一组有标准答案判定规则的开发任务，观察它能否真正完成。

例如：

> 给它一段处理标题的程序，里面有一个空白字符处理错误。让它修改程序。最后由另一段检查程序验证修改是否正确。

你要回答三个问题：

1. 能干活吗？给它 20 道开发题，它做对了多少？
2. 你的设计有用吗？同一个模型，开启与关闭指定机制，结果有什么差别？
3. 出问题时靠谱吗？接口报错、上下文太长、任务争抢时，程序是否按你的设计处理？

“做对”由提前写好的测试决定，不由 CodeAgent 最后一句“已完成”决定。

### 两种 AI，不要混淆

| 本教程的叫法 | 指谁 | 你给它什么 | 它负责什么 |
|---|---|---|---|
| 辅助 AI | 当前这个帮你写代码的 AI 对话 | 下文标着“发给辅助 AI”的提示词 | 制作题目、编写评测程序、分析报告 |
| 被测 CodeAgent | 你项目里的 Agent，由 Python 程序实际启动 | 只有该题的需求和待修改代码 | 阅读、调用工具、修改、验证 |
| 检查程序 | Python 测试，不是另一个自由打分的聊天模型 | CodeAgent 修改后的文件 | 检查结果是否符合规则 |

辅助 AI 可以看参考答案。被测 CodeAgent 不能看到参考答案、隐藏测试或辅助 AI 的出题对话。下文真实运行命令会自动把“题目需求”发给 CodeAgent；不要把整段出题提示词也发过去。

### 只记住四个词

- 任务：一道题。
- 一次运行：CodeAgent 从干净的原始代码开始做一次题。内部可能调用模型和工具很多次。
- 基线组：不启用本次想验证的改进。
- 改进组：启用本次想验证的改进，其余条件保持一致。

## 第 1 步：准备软件，确认从哪里操作

### 这一关解决什么问题

确认电脑能运行项目。不要一开始就安装一堆新软件。

### 需要哪些软件

| 软件 | 用途 | 现在需要做什么 |
|---|---|---|
| 当前 AI 编程工具 | 让辅助 AI 创建文件和测试 | 继续用当前项目对话即可 |
| Windows PowerShell | 输入并运行命令 | Windows 搜索框输入 PowerShell，普通方式打开 |
| Python | 执行项目和检查程序 | 本机已检查到 3.12.7，不需要为教程先重装 |
| Git | 查看改动、记录评测版本 | 本机已检测到 git.exe |
| 浏览器 | 后面查看安装说明，或可选的项目页面 | 已有浏览器即可 |
| Docker Desktop | 正式评测时隔离答题环境 | 第一关先不安装，第 7 步再处理 |

不需要先安装 Excel、数据库管理工具、Postman，也不需要先把项目 Web 前端跑起来。报告先用普通文本和 Markdown，能在当前编辑器打开。

项目使用 Python 自带的 unittest 做基础检查即可，不要求额外安装 pytest。[Python unittest 官方说明](https://docs.python.org/3/library/unittest.html)

### 你现在操作

1. 打开一个 PowerShell 窗口。
2. 把下面命令逐行复制进去，每行按一次 Enter。不要复制命令外面的解释，也不要手动输入 `PS D:\...>` 这样的提示符。

```powershell
Set-Location "D:\new_codeAgent"
Get-Location
python --version
git --version
python -m codeagent --help
```

`Set-Location` 就是“进入这个文件夹”。后面没有特别说明，所有终端命令都在 `D:\new_codeAgent` 执行。

### 看到什么才算通过

- `Get-Location` 显示 `D:\new_codeAgent`。
- Python 版本为 3.11 或更高。
- 最后一条显示帮助文字，包含 `--no-stream`、`--planning-mode` 等选项。

我已在本机验证 `python -m codeagent --help` 能运行。它只看帮助，不会调用模型，也不会产生模型费用。

### 发给辅助 AI：提示词 1

```text
我要按 docs/benchmark-walkthrough.md 给 D:\new_codeAgent 做评估，现在只做环境检查。

请检查 Python、Git、项目导入和 python -m codeagent --help。
检查模型配置是否缺少必要字段，只报告缺少的字段名；不要打印 API Key、Authorization 或完整 .env。
不要调用真实模型，不要安装软件，不要修改项目代码，不要提交或清理 Git。
不要直接采用 README 中可能过时的示例模型名称，以当前配置和代码为准。

请用三部分回答：已经可用；缺少什么；我下一步需要在哪个窗口做什么。
如果失败，给出具体错误原因和一个最小修复步骤，不要一次让我重装整个环境。
```

若报错，把“刚才运行的命令 + 报错文字”发给辅助 AI。包含密钥的内容先删掉。环境没有通过，不继续下一步。

## 第 2 步：先出一道你自己能理解的题

### 这一关解决什么问题

把“测试 Agent 编程能力”变成一件能检查对错的小事。第一题叫 `slug-001`，只是练习题，不代表复杂开发能力。

题目是：把标题转换成网址里的名称。例如 `Hello World` 变成 `hello-world`。

原程序故意写成：

```python
def slugify(text):
    return text.lower().replace(" ", "-")
```

它能处理一个普通空格，但是 `Hello   World` 会产生多个连字符；标题前后的空格也没正确处理。你已经能看出它为什么需要修改，不必先理解整个 Agent 框架。

### 让辅助 AI 创建什么

以下文件由下一段提示词要求 AI 创建，你现在不需要手动新建。文件夹只表示资料分开存放，不等于安全隔离。

| 完整位置 | 放什么 | 给被测 CodeAgent 看吗 |
|---|---|---|
| `D:\new_codeAgent\evals\` | 自动准备、运行、检查的程序 | 不给 |
| `D:\new_codeAgent\eval-lab\tasks\slug-001\baseline\` | 永远保留原样的错题代码 | 只给它的一次性副本 |
| `D:\new_codeAgent\eval-lab\tasks\slug-001\prompt.txt` | 题目需求 | 给 |
| `D:\new_codeAgent\eval-lab\private\slug-001\` | 隐藏测试和参考修复 | 不给 |
| `D:\new_codeAgent\eval-lab\runs\lesson-001\` | 这一次的副本、日志和结果 | 只允许看到 work 子目录 |

练习阶段这些目录同在本机，不能保证 Shell 绝对读不到其他目录，所以这里只做受控演练；第 7 步才验证正式隔离。

### 发给辅助 AI：提示词 2

```text
现在实施教程第 2 步：只制作第一道练习题、检查程序和最小命令入口，不调用模型。

先检查 evals/ 和 eval-lab/ 是否存在，保留已有内容，不覆盖用户文件。
所有新增文件限于这两个目录，不修改 codeagent/，不执行 Git reset/clean，不做 git commit。

制作 slug-001：
1. baseline/slugify.py 内容为：
   def slugify(text):
       return text.lower().replace(" ", "-")
   这段代码故意有错误，请不要提前修复 baseline。
2. prompt.txt 要求：只处理字符串输入；统一小写；去掉首尾空白；连续空白合并为一个连字符；空白包含空格、Tab、换行；保留中文、数字、原有标点；全空白返回空字符串；函数名和参数不变；不要新增依赖。
3. private/slug-001/ 保存参考修复与 unittest 隐藏检查，绝不复制到答题 work 目录。
4. 固定 8 个检查，分别断言这些输入输出：
   "Hello World" -> "hello-world"
   "  Hello World  " -> "hello-world"
   "a   b" -> "a-b"
   "a\tb\nc" -> "a-b-c"
   "" -> ""
   " \t\n " -> ""
   "你好 世界" -> "你好-世界"
   "Room_42.v2" -> "room_42.v2"

用标准库创建 python -m evals 入口，先只支持以下命令：
  python -m evals --help
  python -m evals preflight --task slug-001
  python -m evals prepare --task slug-001 --run lesson-001

preflight 要在两个不同临时目录验证：baseline 至少有一项目标检查失败；参考修复 8 项全通过。条件满足则 preflight 本身退出码为 0，并保存报告。测试没执行、数量不是 8、参考实现未通过时拒绝通过。
prepare 只将 baseline 复制到 eval-lab/runs/lesson-001/work，保存元数据；同名 run 已存在时拒绝覆盖，提示使用新名字。
运行目录中另设 state 和日志，不能混入原项目的个人 Memory 或运行数据库。
文件路径必须限定在本次评测目录，不能用用户传入路径删除其他目录。

完成后运行帮助和 preflight，报告实际创建的文件、实际执行的命令、测试数量和输出。不要说未来命令已经实现。
```

### AI 做完以后，你亲自检查

下面命令只有在提示词 2 已实施成功后才存在。遇到 `No module named evals`，说明尚未创建成功或你不在项目目录，不是让你去安装网上同名的 evals 包。

```powershell
Set-Location "D:\new_codeAgent"
python -m evals --help
python -m evals preflight --task slug-001
```

验收结果应该表达：

```text
原始代码：执行 8 项，存在失败，符合预期
参考修复：执行 8 项，全部通过
出题自检：通过
```

这是预期含义，不是已经测出的输出。原始代码红色失败在这里是好事：说明题目确实有问题，而且检查程序能发现。若原始代码也全部通过，就不能用这题证明 Agent 修好了什么。

## 第 3 步：先测试“检查程序会不会判错”，不花模型费用

### 这一关解决什么问题

如果一个什么都没改的 Agent 只说“完成了”，你的检查程序会不会也给它通过？先把这种错误排除，再调用付费模型。

这里用“假 Agent”：它不请求模型，只按预设动作不修改文件，或者放入已知正确的修复。这是在检查评测程序，不是在测 CodeAgent 能力。

### 发给辅助 AI：提示词 3

```text
实施教程第 3 步，在已有 evals 中增加假运行和独立判分，不调用任何真实模型。

增加这两个命令：
  python -m evals fake --task slug-001 --behavior no-change --run fake-001
  python -m evals fake --task slug-001 --behavior correct --run fake-002

每次从 baseline 新建独立 work，禁止复用上一次结果或覆盖已有 run。
no-change：不改代码，只产生“我完成了”的假回复。
correct：仅在 fake 模式中放入私有参考修复。

执行结束后冻结变更，在另一个干净目录重放变更，再用固定隐藏测试判分；不要只运行 work 里的测试。
正确处理新增文件，不能只用 git diff HEAD 导致新文件消失。
不要让真实运行路径接触参考修复。fake 模式在结果中明确标记，报告不得将其算作真实模型成绩。

每个 run 保存 result.json、agent.log、grade.log、变更文件清单和可重放的补丁。
result.json 至少包含 run_id、task_id、mode、success、failure_reason、grade.tests_run、grade.tests_passed、runtime.model_calls、usage.total_tokens、usage.complete、elapsed_seconds。
未知数据写 null；只有确定没有模型调用的 fake 模式才可写调用数和 token 为 0。

给评测程序自身加自动化测试，至少验证：
1. no-change 判失败，correct 判成功。
2. 删除答题目录里的测试不能骗过外部判分。
3. 新增文件能完整重放。
4. 测试实际执行数为 0 时，不能判成功。
5. 同名 run 不被覆盖，两次运行状态不共享。

最后实际执行两个命令，向我展示真实判分和文件路径。
```

### 你怎么检查

AI 已经运行成功就不用重复执行同名 run，直接查看文件。若你要亲自运行，改用新的名字，例如 `fake-003`、`fake-004`。

```powershell
Get-Content -Raw -Encoding UTF8 "D:\new_codeAgent\eval-lab\runs\fake-001\result.json"
Get-Content -Raw -Encoding UTF8 "D:\new_codeAgent\eval-lab\runs\fake-002\result.json"
```

看不懂整个 JSON 没关系，先找三个位置：

- `fake-001` 的 `success` 必须是 `false`。
- `fake-002` 的 `success` 必须是 `true`，实际检查数为 8。
- 两次都没有真实模型调用。

如果假装完成也得到了成功，不继续下一步。把两个 result.json 和 grade.log 给辅助 AI，要求只修判分逻辑，不能改题目让它变容易。

## 第 4 步：接上你自己的 CodeAgent，先准备，不立刻花钱

### 这一关解决什么问题

让刚才的自动流程调用你项目的真实 Agent Loop，而不是辅助 AI 自己把题做完，也不是另外写一个简化版 Agent 冒充你的项目。

### 发给辅助 AI：提示词 4

```text
实施教程第 4 步：为 evals 接入当前 CodeAgent 的单任务运行。先实现并做假客户端测试，不调用付费模型。

先读 codeagent/agent.py、codeagent/web/factory.py、codeagent/config.py、codeagent/anthropic_client.py、codeagent/runtime/data_paths.py，说明复用哪些现有接口。
复用真实 Agent Loop、工具和权限检查；不要让辅助 AI 直接给作答目录写入参考答案，也不要另造 Agent Loop。

增加命令：
  python -m evals doctor
  python -m evals run-one --task slug-001 --profile pilot --run real-001 --allow-api

doctor 不调用模型。只显示模型名称、所需配置是否齐全、隔离状态、程序是否可用；密钥只显示已配置/未配置，不输出值。
连接信息使用用户已有配置，不替换模型、不修改个人 .env。缺配置就停止并只问缺少的字段。若摘要开启，也检查摘要模型配置。

run-one 自动准备全新 work，只将 prompt.txt 的题目需求交给被测 Agent。
显式绑定该 work 为工具工作区；每次独立 state、Memory 和消息历史；pilot 关闭 Memory、Skill、MCP、子 Agent、Team，保留真实权限门禁。
SDK 重试显式设为 0；pilot 禁止 fallback，记录框架恢复的有效配置。

pilot 预设：整个运行最多 10 个逻辑模型请求（包括摘要和重试），根循环最多 10 轮，每请求输出最多 2000 token，180 秒截止，单工具 30 秒。总 token 20000 是软上限，返回后可能超出，要如实标记。
触发上限后不接纳新请求；外部控制器终止本次所属进程，验证没有遗留 Shell。不能只取消 Future 就说终止完成。
记录所有调用和可用的 provider usage，漏 usage 标为不可用，不能写 0；不要记录密钥或推测隐藏思维链。

结束后使用第 3 步独立 grader，保存同样的结果和日志，附真实配置与模型信息。
缺少 --allow-api 时不发送真实请求，而是说明将使用的模型、上限和结果目录。该开关允许的是一次有上限运行，不是只允许一个模型请求。
先用假客户端证明它真的调用项目 Agent，补足超时、预算、作用域和状态隔离测试。

结束时给我可以执行的命令，但等我自己确认后才运行真实 API。
```

### 你怎么验收

在 PowerShell 输入：

```powershell
python -m evals doctor
```

确认：模型是你打算测试的；必要配置齐全；没有显示任何 API Key；真实调用数是 0。先不输入真实运行命令。

第一轮允许在明确标记“本地受控练习”的环境做这道无危险动作的小题。它不构成隐藏答案不可访问或安全沙箱已验证的证据。想直接进行正式隔离运行，可先完成第 7 步再返回。

## 第 5 步：让 CodeAgent 真正做第一题，然后看结果

### 这一关解决什么问题

完整走一遍“给题 → 自动修改 → 独立检查”。从这一关开始可能产生模型费用。

### 被测 CodeAgent 实际收到的问题

这段内容应位于 `D:\new_codeAgent\eval-lab\tasks\slug-001\prompt.txt`。你可以在当前编辑器打开它核对。程序会自动发送，不需要你另外打开项目网页。

```text
请修复当前项目 slugify.py 中的 slugify(text) 函数。

要求：
1. 输入保证是字符串。
2. 英文字母转换成小写。
3. 去掉首尾空白。
4. 将连续的空白字符转换成一个连字符，空白包括空格、Tab 和换行。
5. 保留中文、数字和原有标点。
6. 输入为空字符串或全部为空白时，返回空字符串。
7. 保持函数名和参数不变，不安装新的依赖。

请阅读现有代码，完成修改并自行验证。最终简要说明改动与验证结果。
```

题目里必须写清楚要求；“隐藏测试”只能隐藏检查用例，不能隐藏需求再扣分。

### 你现在操作

1. 确认第 4 步 doctor 已通过。
2. 确认愿意花一次受限运行的模型额度；具体费用取决于你的服务，不在这里承诺金额。
3. 在 PowerShell 输入：

```powershell
Set-Location "D:\new_codeAgent"
python -m evals run-one --task slug-001 --profile pilot --run real-001 --allow-api
```

4. 等程序结束。不要在它作答时让辅助 AI 修改同一个 work。
5. 查看结果：

```powershell
Get-Content -Raw -Encoding UTF8 "D:\new_codeAgent\eval-lab\runs\real-001\result.json"
Get-Content -Encoding UTF8 "D:\new_codeAgent\eval-lab\runs\real-001\grade.log"
```

同名运行已存在时，不删除旧记录，换 `real-002`，相应查看路径也换成 `real-002`。

### 看到什么才算完成这一关

你能找到以下四件东西，成功或失败都算流程跑通：

1. CodeAgent 真正改了哪些文件。
2. 检查程序实际运行了多少条，哪些通过、哪些失败。
3. 本次使用哪个模型，调用多少次，花了多久。
4. 最终 `success` 和失败原因。

`success=true` 要求题目检查通过、操作范围符合规定、没有超时或超预算、关键证据有效。不是“模型给了回复”就算成功。token 缺失但其他证据有效时，可保留任务结果，但不能填写精确费用。

如果你怀疑检查结果，发给辅助 AI：

```text
请只读分析 eval-lab/runs/real-001 中的 result.json、grade.log、脱敏调用日志和候选补丁。
不要修改作答文件，不要修复答案，不要重新调用模型，也不要覆盖原始记录。
请分别解释：模型实际做了什么；检查程序为什么给这个结果；问题属于 Agent 失败还是评测程序错误；还缺什么证据。
```

## 第 7 步：正式测试前，把答题区和答案区真正隔开

### 这一关解决什么问题

只把答案放在另一个文件夹，不能保证有 Shell 工具的 Agent 读不到。正式评测需要限制它实际能访问什么，也要避免它改到你的原项目。

这里增加 Docker Desktop：把答题过程放到一个受限、临时的运行环境里。它不是安装以后自动安全，还需要正确配置和验证。

### 从哪里操作

1. PowerShell 运行 `docker version`。如果同时显示 Client 与 Server 信息，说明命令和后台服务可用。
2. 若提示找不到命令，使用浏览器打开 [Docker Desktop Windows 官方安装页](https://docs.docker.com/desktop/setup/install/windows-install/)，先核对系统要求，再下载与你电脑架构匹配的安装包。
3. 按安装向导操作；Windows 功能、WSL 或重启要求先确认再执行，不盲目修改系统设置。
4. 安装完成后，从 Windows 搜索打开 Docker Desktop，处理它显示的启动要求。
5. 返回 PowerShell，再执行 `docker version`。只有 Client、没有 Server，通常还需要启动或排查 Docker 后台。

如果安装卡住，给辅助 AI 发“当前步骤 + 报错文字”，让它先诊断你的系统条件，不要为了跑练习强行改 BIOS 或重装系统。不方便安装时可以停在本地演练，报告明确写“本地受控验证”，不宣称已验证强隔离。

### 发给辅助 AI：提示词 6

```text

正式模式要求：
1. 每次全新执行环境，只提供当前任务的基线副本和被测 codeagent 包，不能挂载整个 D:\new_codeAgent。

```

这一步可能比前面的练习耗时长。它完成之前，不运行真实危险命令测试，也不将本地演练包装成严格隔离的正式成绩。

验收命令：

```powershell
python -m evals isolation-check
```

它必须检查真实的访问限制，不能只检查配置里写着 `sandbox=true`。

## 第 8 步：设置两个组，才知道你的改进有没有作用

### 这一关解决什么问题

只跑完整版，能知道它做对几题，但不知道“是模型本来就会，还是你写的机制有帮助”。所以同一道题要让两个配置都做。

本轮只问：上下文治理和错误恢复这组机制，整体有没有帮助？不同时评估 Memory、Skill 和 Team。

| 条件 | basic 基础组 | governed 治理组 |
|---|---|---|
| 模型、题目、基础工具、权限 | 相同 | 相同 |
| 总时间、模型请求数等预算 | 相同 | 相同 |
| 历史压缩、额外大输出治理、框架恢复 | 关闭 | 开启 |
| SDK 自动重试、fallback | 关闭 | 关闭 |
| Memory、Skill、MCP、子 Agent、Team | 关闭 | 关闭 |

如果治理组更好，只能说这个组合在这批题上更好。要说“具体是压缩带来的”，要在第 10 步做只改压缩开关的实验。

### 发给辅助 AI：提示词 7

```text

把两组配置保存到 evals/profiles/basic.json 和 governed.json。配置文件不包含密钥。
严格落实教程第 8 步对照表，输出两组最终生效配置的差异。

开发阶段建议预算：全 trial 最多 30 个逻辑模型调用、600 秒截止、单工具 60 秒、每请求输出不超过 4000 token、总 token 100000 软上限。计入摘要和重试；软上限不是精确费用上限。
governed 的框架重试、续写也应有独立上限，耗尽后明确停止。所有有效值进入结果文件。

如必须修改 codeagent/，先说明最小修改位置并保留用户已有改动，只实现本步骤需要的开关和观测。添加行为测试证明两组真正不同，而不是只比较 JSON。
```

### 先只用同一练习题各跑一次

下面会产生费用；前面的实现、配置和隔离都通过后才执行。两个命令从不同的原始副本开始，不共用第一次修好的代码。

## 第 9 步：制作正式题单，然后批量跑

### 这一关解决什么问题

把一次演示变成可重复的小规模实验，并避免只留下做得好的案例。

练习题用于调试，不并入正式分数。建议正式集先做 20 道：8 道缺陷、8 道功能、4 道重构，来自至少 3 个仓库。这个数量是个人项目的起点，不是统计保证；预算不够可预先缩小并如实说明。

### 发给辅助 AI：提示词 8，先找题，不立即开跑


## 第 10 步：单独测“压缩以后还记不记得要求”

### 要解决的问题

你的 Context Compact 可能让消息变短，但是否把重要要求也丢了？所以同时检查“变短多少”和“最终有没有做错”。

先制作一个受控练习：最早告诉 Agent 三个约束，中间插入较长、结构合法的历史，最后要求它按原要求写功能。

被测 CodeAgent 最早收到：

```text
稍后请给程序增加 CSV 导出。请记住：默认输出编码必须是 utf-8；默认最多导出 100 条数据；命令行参数必须叫 --limit。不要修改现有公开函数名。
```

历史变长后，最后收到：

```text
现在请按前面约定完成 CSV 导出功能，并验证正常输入、默认参数和边界行为。
```

中间历史由评测程序准备，你不用手动粘贴几万字，也不要把“正确答案代码”混进去。

### 发给辅助 AI：提示词 10

```text

最终独立检查编码、默认条数、参数名称、公开接口和导出内容是否正确。

  python -m evals plan --set context-dev --profiles context-off context-on --repeat 1 --experiment context-pilot
先做假模型测试和配置核验，不自动调用真实模型。提供计划、运行和报告的准确命令。
```

这个练习调通后，再准备独立的 8 道上下文正式题，每组重复 3 次，共 48 次。不能拿已反复调整过的 context-001 单题当作正式泛化成绩。

## 第 11 步：测错误恢复和安全，不要靠让模型“假装报错”

### A. 错误恢复到底怎么测

你不能只对模型说“请假装 API 报错后重试”，那是在测它会不会描述重试，不是在测框架真的能否恢复。

正确办法：用假客户端替换网络接口，让程序实际收到指定异常。例子：第一次 429，第二次 429，第三次返回合法响应。检查框架是否按配置执行到第三次。

### 发给辅助 AI：提示词 11

```text
请给 evals 增加恢复控制测试，不请求真实网络，不花模型额度。
复用项目现有 RecoveryRuntime 和客户端注入方式，用假客户端实际抛出与 SDK 兼容的异常；不要写一个只返回“恢复成功”的假恢复器。
先覆盖 6 类：
1. 429、429、成功：框架允许 2 次重试时，应共尝试 3 次后完成。
2. 持续 429：耗尽后明确失败，不死循环。
3. 401：不可恢复认证错误，不反复重试。
4. 摘要失败：不损坏原历史。
5. 工具写入已发生但结果未确认：按结果不确定处理，不盲目重复非幂等写入。
6. 工具超时：按协议停止，并验证本次所属进程得到清理。
SDK 重试显式为 0；普通退避用假时钟，少量真实超时边界用受控临时进程。
区分“最终恢复”与“按预期失败”：401 正确失败也是控制测试通过，但不是恢复成功。
用调用计数和实际标记变化验证副作用，不只看文本日志。
实现 python -m evals reliability --suite recovery，保存逐案例报告到 eval-lab/reliability/recovery/。
完成后运行测试，报告预期与实际尝试数、最终状态和副作用，不伪造结果。
```

你在 PowerShell 执行已实现的命令，再打开该目录的 `report.md`：

```powershell
python -m evals reliability --suite recovery
```

这里不需要向被测模型发送题目。第一阶段验证的是控制代码；要证明真实模型能理解工具错误反馈，再单独补真实任务实验。

### B. 安全到底怎么测

先判断三件事：正常操作能做吗？危险操作会要求确认或拒绝吗？拒绝以后底层操作有没有真的执行？

### 发给辅助 AI：提示词 12

```text
请增加安全策略测试，只使用假 handler、无价值临时文件和受控模拟服务，禁止真实破坏性命令、真实外部发送和工作区外写入。
复用项目的实际权限 Hook 和 Team Gate，不另写一套更安全的逻辑冒充当前实现。
先做少量易理解的 allow/ask/deny 案例：项目内普通读取；允许范围内编辑；要求确认但未确认的操作；明确禁止的工作区外写入；失效 lease 提交。
预先根据明确策略给每条标注期望。检查决策，并用 spy handler 计数证明拒绝/尚未确认时没有调用实际操作。
写后审计检测出的越界要单列，不能算“执行前成功拦截”。不适用平台场景标 skip，不算通过。
实现 python -m evals reliability --suite safety，保存到 eval-lab/reliability/safety/。
扩展测试矩阵后可做到 50 条正常、25 条需确认、25 条拒绝的不同案例，但不要重复同一输入凑数。
先运行假测试，告诉我实际通过、失败和未覆盖项。不宣称有限样例通过就证明任意命令安全。
```

验收时你要能打开一条失败案例，看清“输入是什么、期望是什么、实际做了什么”。只展示一个总通过率不够。

## 第 12 步：测多 Agent，不要只开三个聊天窗口比快慢

### 要解决的问题

并发可能更快，也可能因为沟通和验证而更慢、更贵。先固定同一份分工，只改变同时工作的 worker 数量。

项目里的普通 subagent 调用不等同于后台 Team 并行调度。本步骤要复用真实 TeamSupervisor、DAG、Worktree 和候选验证流程。

### 第一份并行练习设计

准备一个整数金额的示例程序，输入保证合法，用整数分避免小数舍入争议。将同一需求固定拆为三项，文件互不重叠：

| 子任务 | 被测 worker 收到的具体需求 | 固定检查 |
|---|---|---|
| 1 | 在 subtotal.py 实现 subtotal(items)，items 含 unit_cents、qty，返回各项单价乘数量之和，空列表返回 0 | 空订单、单项、多项 |
| 2 | 在 shipping.py 实现 shipping_fee(subtotal_cents)，满 10000 分免运费，否则 800 分 | 9999、10000、10001 |
| 3 | 在 receipt.py 实现 render_receipt(name, total_cents)，返回字符串“姓名:整数分金额”，不加空格和换行，保留中文 | ASCII 姓名、中文姓名、0 |

预先提供 checkout.py 调用这些固定接口，最后整体检查“商品小计 + 运费”和收据输出。三个 worker 不自行重新设计接口，也不彼此覆盖文件。

这道题很小，未必产生加速，它首先用于证明实验能跑通。正式集还要加入依赖链和不能并行的控制任务。

### 发给辅助 AI：提示词 13

```text
请按教程第 12 步制作 team-dev 练习，复用现有 TeamSupervisor、任务认领、Worktree、lease 与候选验证。
固定三项任务、文件范围和接口，预先固定低风险审批规则。
两组共用同一计划、同一模型、同一总预算：team-1 同时最多 1 个 worker，team-3 同时最多 3 个 worker。
核对 max_teammates 和批准计划中的实际人数；保持其他线程池设置相同，并记录实际活跃 worker 数，不能把线程池大小当作并发实测值。
不要把每个 worker 都分到单 Agent 的全部预算。汇总 Lead、worker、摘要和后续 run_id 的全部调用。

分别记录：已批准计划开始到全部候选通过约定验证；候选机械组合并经最终独立测试完成。初始规划不在第一项计时内，报告须说明。
现有产品不自动集成时，由评测器在独立环境按固定顺序应用候选并运行最终测试，注明这是评测侧操作；冲突不允许人工修好后算无人辅助成功。
所有 Git 初始化或临时操作仅限评测工作区，不能修改原项目提交历史，不使用全局 Git 配置。

增加并验证：
  python -m evals plan --set team-dev --profiles team-1 team-3 --repeat 3 --experiment team-pilot
先用假客户端核验调度和判分，提供随后 run-plan/report 命令，不自动调用模型。
保存实际并发、等待、返工、候选补丁、集成结果、总 token、用量缺失和耗时。
```

一题 × 两组 × 三次 = 6 次练习。真正报告并发收益时，再换成 6 个未参与调试的固定 DAG，每组三次，共 36 次，并报告共同成功样本上的耗时比和两组完整成功率。

如果要验证“模型自己会不会拆任务”，需要另一个端到端实验：从自然语言需求开始计时，计划失败也算失败，规划和人工等待全部记录。固定分工实验不能证明自主规划能力。

## 第 13 步：读报告、写简历、准备面试

### 先看这几项，别一开始做几十张图

| 你关心的问题 | 报告里看什么 |
|---|---|
| 做对几次？ | 成功次数/实际运行次数，以及计划完成了多少 |
| 改进有用吗？ | 两组成功率差；没提升也如实写 |
| 快吗？ | 两组共同成功任务的配对耗时，同时列成功覆盖率 |
| 贵吗？ | 包含失败、摘要、重试的总调用/token；usage 不全就注明 |
| 会忘要求吗？ | 压缩触发、早期约束检查、最终功能结果 |
| 会乱重试或乱操作吗？ | 故障预期符合、重复副作用、误拒绝、写后检测 |

八个检查条件只是第一题的八项检查，不能说成八个开发任务。20 道题每组各做 3 次，每组分母通常是 60 次尝试，不是 60 道独立任务。

举一个纯计算例子，以下不是你的实际结果：基础组 30/60、治理组 36/60，则成功率从 50% 到 60%，增加 10 个百分点。不能写成“提升 10%”而不解释是百分点还是相对比例。

不要把“三次里至少一次成功”冒充“一次成功率”；超时不能删；只统计成功运行的成本会漏掉失败代价。若比较耗时只用了两组共同成功的部分，也要说明用了多少条。

### 发给辅助 AI：提示词 14

```text
请只读分析本次冻结实验的结果，自动生成 report.md 和 summary.json，不调用模型重做题，也不修改原始记录。
先核对计划数、已开始数、已归档数、失败数、未运行数和缺失证据。
每个指标写清分子、分母、使用哪些 trial_id；fake、dev、本地演练与正式集分开，不混算。
区分任务失败与基础设施异常，保留全部记录。对后者可增加单独口径，但不能不说明就剔除。
列出两个成功案例、两个失败案例和一个性能/成本取舍，每项关联日志、补丁和固定判分。
费用或 token 缺失就写不可用，不补估成 0。数据规模小不编造显著性或泛化结论。
最后给我三段：这些数据能证明什么；不能证明什么；可用于简历的真实表述。不要为追求提升修改措辞或挑样本。
```

### 简历上的结果占位怎么留

个人草稿可以写：

> 构建面向多步开发任务的 Agent 框架及自动评估流程，在 __ 个仓库、__ 道固定任务上开展同模型、同预算对照；任务成功率由 __ 变为 __，总 token 消耗 __，每成功一次的摊销成本 __。（待实测）

> 针对任务依赖和并行写入冲突，实现 DAG 调度与 Worktree/lease 协作；在 __ 组固定任务分工上比较单 worker 与 __ worker，候选就绪耗时比 __，最终验证通过率 __。（待实测）

投递之前，没有测出的字段就删掉，不把“待评估”的计划写成完成成果。没有明显提升时，也可以写“建立可复现评估，识别摘要开销/集成等待等瓶颈”，前提是你真的做了相应分析。

### 面试时至少能讲清楚这一条完整链路

选一题，说清：原程序有什么问题 → 给 CodeAgent 的需求是什么 → 它实际改了什么 → 检查程序如何判定 → 这次花了多少调用/时间 → 是否有失败和限制。

不要只背总分。能打开一份失败轨迹解释原因，通常比只展示漂亮数字更容易让对方理解你的工程工作。

## 常见卡点：遇到什么，下一步怎么做

| 你看到的情况 | 通常先检查什么 | 给辅助 AI 的明确要求 |
|---|---|---|
| `No module named evals` | 是否在项目根目录；对应提示词有没有真正实施 | 检查入口与当前目录，不要安装网上同名包 |
| `Missing required environment variable` | 缺哪一个配置字段 | 只报告字段名，指导我在本地填写；不公开密钥 |
| 401/认证失败 | 凭证、服务地址、模型兼容性 | 先诊断，不重复付费调用，不改换模型掩盖问题 |
| 摘要模型缺配置 | 当前是否启用了摘要 | 核对真实配置，不默默关闭后继续声称测的是治理组 |
| `Ran 0 tests` | 测试发现路径、文件命名、导入方式 | 修复判分器；0 项不是通过 |
| 参考修复也失败 | 题目、参考修复或环境是否有问题 | 停止出题自检，先修题，不让 Agent 背锅 |
| run 名已存在 | 同名运行已有结果 | 使用新编号，保留旧结果 |
| 模型说完成但 success=false | grade.log、预算和权限结果 | 解释具体失败，不能直接把结果改 true |
| 两组一样 | 是否真的有机制触发；题是否太简单 | 先看日志；只在开发集调整，正式负结果保留 |
| Docker 只有 Client | 后台未启动或连接失败 | 检查 Docker Desktop 状态，不自动降级为宿主执行 |
| 一直没有结束 | watchdog 是否有效，是否残留子进程 | 停止新请求，按 trial 精确清理，不终止所有 Python 进程 |
| token 是 null | 提供商是否返回，采集是否遗漏 | 核对原始 usage；不知道就保留 null |

通用求助格式，直接复制：

```text
我在教程第 __ 步。
使用的软件是 __，当前目录是 __。
刚才运行的完整命令是：__。
实际输出或报错是：__。（已删除密钥）
我原本应该看到：__。
请先只读诊断，说明原因；如果需要修复，只改与这一步有关的文件。
不要跳过失败继续后面的步骤，不要覆盖已有实验结果，不要自动调用付费模型。
```

## 其它能力什么时候测

Memory、Skill、MCP、定时任务先不与主实验混在一起。完成前面的流程后，再选对你简历最重要的一项：

- Memory：第一次会话记录项目约定，第二次全新会话提出相关任务；检查是否正确使用记忆，并加一条过期/无关记忆观察误用。
- Skill：给出需要特定项目流程的任务；检查是否选对技能、是否按步骤执行、最终结果是否正确，另外准备不需要技能的题。
- MCP：用本地假服务测试工具发现、参数、超时、取消和权限，不用真实邮件或生产数据库练手。
- 定时/重启：用假时钟和临时数据库，检查任务按时触发、重复唤醒不重复执行、重启后的真实恢复粒度；先不以付费模型作为定时动作。

发给辅助 AI 的扩展提示词：

```text
主评测已跑通，这次只为 __ 能力设计一个最小实验。
请按以下格式给我操作教程：要证明什么；用哪个软件；在哪个目录操作；给被测 Agent 的完整需求；固定检查；对照条件；新增哪些文件；逐条运行命令；结果在哪看；什么算失败。
先给一个我能理解的具体例子，不同时扩展其他能力。未实现的命令明确标记，并先做假客户端或模拟服务验证。不要直接调用真实外部服务。
```

公开 SWE-bench 可作为以后补充，不是本教程的入门前提。自建题集应称为自建评估，公开题子集应写清具体来源、版本和题数；不能把它们都称为官方完整榜单成绩。

## 你今天就按这个顺序做

1. PowerShell 跑第 1 步的环境命令。
2. 把提示词 2 发给辅助 AI，要求它创建第一题和检查程序。
3. 自己运行 `preflight`，确认“错题失败、参考修复通过”。
4. 把提示词 3 发给辅助 AI，验证“不改就失败、正确修复才通过”。
5. 到这里先停一下：你应该已经能解释一题如何被判分。再进行真实模型接入。

这份教程现在只提供操作说明和提示词，没有替你实施 evals、创建题库或启动模型评测。每一步都要等前面的程序真正创建并验收通过，才能运行相应命令。
