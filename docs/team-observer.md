# Team 执行观察面板

启动新版后端并刷新前端，在右侧「团队」中点击「打开执行观察面板」。
建议先从「全部流程」顺序阅读，再选择「团队通信」「工具执行」「工作目录与写权限」等表。
点击记录，右侧显示数据库字段名、中文说明、旧值和新值。用「上一步 / 下一步」逐条阅读，
用「到最新」查看最新变化；搜索支持任务名称、Agent 名称、ID、字段和状态。

## 记录什么

`database_changes` 是只追加的诊断历史，不参与认领、调度、审批或恢复。
`team_observation.py` 明确列出当前 28 张业务表；每表的 SQLite 触发器记录全部列。
新增记录保存 after，更新保存 before 和 after，删除保存 before。无变化的 UPDATE 不记录。
触发器与业务写入处于同一事务：回滚不会留下假日志。序号是数据库行变化顺序，
不是每个序号都代表一次独立事务，也不是墙钟时间或模型调用编号。

首次启用时，已有行记录为 `snapshot`，不能还原启用之前的变化；重启不重复创建快照。
新版本启用后的任务创建、方案拒绝/批准、消息投递/确认、上下文存档、工具结果、
Worktree 冻结/恢复、候选审查及测试提交都可观察。记录窗口不依赖浏览器是否打开。

为了不漏掉 Team 创建前的任务、用户消息和主循环，数据库同时记录普通单 Agent 的表变化。
面板按 Team 专属数据、关联任务列表、关联会话运行、历史 Session 和消息 ID 查询。
**共享任务列表和会话运行记录可能包含该列表/会话内其他 Team 或单 Agent 的活动。**
要得到最清楚的一次运行记录，使用独立会话和任务列表测试。

## 接口与刷新

- `GET /api/teams/{id}/changes?after=0&limit=100`：按序号分页的简要变化，最多 200 条/页。
- `GET /api/teams/{id}/changes/{seq}`：该 Team 范围内某条变化的字段详情。
- 接口使用现有本机访问与会话安全机制，不提供修改数据库的入口。
- 面板打开后按持久化游标追赶历史，追上后每 2 秒读取新增记录；不是对当前状态做抽样。
- 读取失败保留已加载记录，从原游标重连；关闭 / 刷新后重新从数据库加载。
- 默认隐藏纯心跳及部分底层事件，不删除它们；勾选「包括心跳、存档及底层事件」或选定该表可查看。

## 边界和代价

- 只保证已监控表的数据库行变化。不会记录未落库的 LLM 思考、每次文件读写的实际字节或外置文件的内容变化。
- 外部程序删除触发器、直接替换数据库文件、修改表结构不属于支持的记录路径。
- 普通 SQLite INSERT / UPDATE / DELETE 由触发器捕获；不要用外部 `REPLACE` 代替业务更新。
- 原始 before / after 完整保存在本地数据库，可能含上下文、工具参数和私密内容；保护数据库和备份，勿直接公开。
- 页面 JSON 字段以解码后的形式显示并复用已有敏感信息脱敏规则；超长文本（128 KiB）与超过 64 层的嵌套明确标为截断。数组不静默截取前 200 项。
- 记录历史会增加数据库体积和写入开销，尤其是上下文存档。当前不自动删除历史、不增加清理操作，不改变预算或执行权限。
- 单 Agent、同步 Subagent、Task DAG 和 Team 状态机不变。数据库写入失败时仍走现有异常处理，不偷偷丢弃观察记录继续执行。

覆盖全部业务表、全字段、新增/更新/NULL/删除、级联删除、事务可见性与回滚、
无效 UPDATE 不留假日志、审批命令幂等、持久化分页、重启、旧数据库初始快照、
消息投递与确认、历史 Session、跨 Team 详情隔离、只读接口和敏感字段预览。
