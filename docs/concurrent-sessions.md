# Web 多会话并发设计与验收

## 行为与范围

- 一个 Web 进程维护现有 FIFO 队列和固定 N 个线程；默认 N=4。
- `CODEAGENT_WEB_MAX_CONCURRENT_RUNS` 必须是正整数；1 表示原来的串行执行。
- 不同会话（包括同一项目的会话）可同时运行。同一会话仍最多一个 queued/running Run，重复提交返回 409，不新增会话内消息队列。
- 等待用户回答、审批和模型重试仍占一个名额；取消仅作用于指定 Run。
- 此限制只包含主 Run，Team Supervisor 保持独立配额。
- 项目文件继续共享，不自动创建 worktree；文件编辑冲突不属于运行状态隔离的保证。

## 实现步骤

1. **调度器与配置**：将单 `_thread` 改为 `_threads`，保留 Queue、同步 Agent 和 `_execute`。同一短锁保护提交登记/入队、启动、取消与开始执行的交接，不包住 Agent 执行。数据库的活动会话唯一索引继续兜底。每个 worker 对单任务异常做隔离，始终清理 controls 和 queue 计数。
2. **关闭语义**：进入 stopping 后拒绝提交，不允许 submit 隐式重新启动；取消全部 Run，给每个线程一个结束信号，等待所有线程退出后关闭 factory。有限超时未退出时抛 TimeoutError，保留资源，允许随后再次 stop 等待；不提前关闭运行中的连接。重复 stop 幂等。
3. **MCP**：沿用 factory 的共享字典，加一把共享 RLock；key 包含配置路径、工作区和 cwd 策略。Router 启动加锁，所有调用等待同一 ready 事件并收到相同启动错误。reload 只移出缓存，旧 router 留到服务关闭，正在执行的任务继续使用；不引入引用计数池。启动/关闭互斥，关闭后的实例不复用。
4. **Memory**：复用现有项目 RLock，增加只读锁入口，列表和加载在同一锁内读取。保留既有 Team 写入权限与写操作协调。
5. **前端状态**：草稿按 conversationId 保存；发送/取消/审批使用 React Query 的全部 pending mutation 按目标 ID 过滤，避免只看最后一个请求。发送成功仅清除该会话的已提交草稿。当前会话详细 SSE + 活动期间 2 秒会话摘要轮询；摘要补充 latest_run_id 和待回答标记，刷新后也能回看后台完成任务。
6. **事件补播**：不根据 GET Run 的终态提前断开 SSE；由服务端明确发送补播完成标记。服务端分批读到尾部，确认调度器已释放该 Run 后才关闭，避免状态先写入、终态事件尚未写入时漏事件。前端看到完成标记后关闭连接。

## 验证顺序

- 用 Event/Barrier 控制假 Agent：并发达到 N、第 N+1 排队、释放一个槽后继续、同会话冲突、取消隔离、失败后线程继续、等待回答/审批不阻塞其他槽。
- 关闭/提交交错、有限关闭超时保留资源、重复关闭、事件/消息/checkpoint 不串会话。
- MCP 并发首次初始化只创建一个 router；所有调用等待工具发现；reload 不关闭在用 router；不同 workspace 不共享 cwd 绑定。
- Memory 读取与批量替换互斥，Discuss/Team 只读语义保持。
- API 配置、会话待回答摘要、完整 SSE 补播（超过一页、终态写入与事件写入间隙）。
- 前端类型检查、生产构建及针对会话草稿、并行提交、后台完成回看的交互验证。
- 最后运行相关回归并复核 diff。保留工作区已有修改，不提交或重启用户正在运行的服务。
